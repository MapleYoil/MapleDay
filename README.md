# 메요일 · MapleDay

WinUI 3 기반 메이플스토리 유틸리티입니다.

GitHub: [MapleYoil/MapleDay](https://github.com/MapleYoil/MapleDay) · 앱의 설정에서도 저장소 주소를 열 수 있습니다.

## 라이선스

**수정하거나 배포할 경우 ‘메요일 (MapleDay) — MapleYoil’과 원본 저장소 주소를 반드시 표시해야 하며, 상업적 이용은 절대 금지합니다.** 무료 배포나 출처표시만으로 상업적 이용이 허용되지 않습니다. 수정본에는 수정 사실을 밝히고 라이선스와 기존 출처 고지를 유지해야 합니다. 전체 조건은 [LICENSE](LICENSE)를 확인하세요. 폰트·게임 에셋·외부 라이브러리는 [제3자 자료 고지](THIRD_PARTY_NOTICES.md)에 따라 각 권리자의 이용 조건이 적용됩니다.

## 실행

GitHub [Releases](https://github.com/MapleYoil/MapleDay/releases)의 `MapleDay-Setup-버전-x64.exe`로 설치할 수 있습니다. 설치 프로그램은 현재 Windows 사용자 계정의 앱 폴더에 설치하고 시작 메뉴 바로 가기와 제거 기능을 제공합니다. 바탕 화면 바로 가기는 선택 사항입니다. 개발용 MSIX를 직접 설치할 때는 릴리즈의 공개 인증서와 설치 안내를 확인해주세요.

최신 Windows x64용 실행 파일은 `artifacts/MapleDay/MapleDay.exe`입니다. 실행 폴더에는 `MapleDay.exe`와 `App` 폴더만 있습니다. DLL·언어 폴더·에셋·런타임과 앱 본체는 전부 `App` 안에 둡니다. 바깥의 `MapleDay.exe`는 Windows 시스템 DLL만 사용하는 네이티브 실행기로, 자기 위치를 기준으로 `App/MapleDay.exe`를 실행하고 인자를 전달합니다. Windows의 숨김 속성은 사용하지 않습니다. 배포 폴더 전체를 유지한 상태로 실행하세요. .NET과 Windows App SDK 런타임이 함께 포함됩니다.

빌드와 배포 모두 프로젝트의 `SelfContained=true`를 사용하여 .NET 런타임 의존성 목록을 일치시킵니다. `scripts/Publish.ps1`은 `Verify-Runtime.ps1`로 `MapleDay.deps.json`의 런타임 항목·실제 파일을 검사하고, 네이티브 .NET 호스트 초기화까지 검증합니다. 이 검사는 앱의 Main이나 WinUI 창을 실행하지 않습니다. MSIX 검증에서도 런타임 의존성 목록과 포함된 파일을 검사합니다.

기본 글꼴은 Pretendard입니다. 공식 v1.3.9의 가변 TTF와 SIL OFL 1.1 라이선스를 앱의 `Assets/Fonts`에 포함하므로 별도 폰트 설치가 필요하지 않습니다. 제목·본문·버튼·입력창·사이드바에 적용하며 기존 굵기 설정을 유지합니다.

기본 창 크기는 1200×800px입니다. 이미지의 픽셀 크기와 원본 좌표를 유지합니다. 모든 캐릭터에 쵸코마린 기준 원본 좌표 `(89,103)`에서 108×120px인 동일한 영역을 적용합니다. 개별 캐릭터의 투명 여백이나 탈것에 따라 다시 가운데 정렬하지 않습니다. 실제 그림이 68×80px인 쵸코마린에는 상하좌우 20px 여백이 생기며, 영역 밖의 큰 그림은 잘립니다.

닉네임 위에는 월드 아이콘과 서버 이름을 표시합니다. 제공받은 넥슨 월드 아이콘 19개는 `src/MapleDay/Assets/Worlds`의 로컬 PNG 에셋으로 포함하며 실행 중에는 다운로드하지 않습니다. 매핑되지 않은 월드는 서버 이름만 표시합니다.

로고는 GameLauncher.exe에 포함된 최대 해상도 256×256px 버섯 아이콘에 파란 달력 배지를 덧붙였습니다. 원본 버섯은 그대로 유지합니다. 로고와 앱 아이콘·파비콘은 `src/MapleDay/Assets/Branding`에 있으며, 앱 헤더·제목 표시줄·실행 파일에 적용했습니다. ICO에는 16~256px 크기 7개를 포함합니다.

1. 메요일을 실행하고 메이플스토리용 넥슨 Open API 키를 직접 입력합니다.
2. **캐릭터 불러오기**를 누르거나 Enter를 누릅니다.
3. 계정 전체의 캐릭터가 레벨 내림차순으로 표시됩니다.

목록 상단의 **전체 서버** 필터에서 서버 아이콘과 이름을 선택하면 해당 서버 캐릭터만 표시합니다. 서버 필터는 문의에 사용할 캐릭터 목록이나 스케줄러 등록 목록에 영향을 주지 않습니다. 각 카드의 **스케줄러에 추가** 버튼으로 등록하며, 등록된 카드는 **스케줄러에 추가됨**으로 표시됩니다. 스케줄러에서 제거하면 다시 추가할 수 있습니다.

캐릭터 목록·기본 정보·표시 이미지는 `%LOCALAPPDATA%\MapleDay\character-cache\<키 해시>.dat`에 키별로 현재 Windows 사용자용 암호화로 저장합니다. 이전 `characters.dat`도 읽을 수 있습니다. 다음 실행에는 저장된 키와 일치하는 캐릭터 정보를 복원하고, 백그라운드에서 스케줄러에 등록한 캐릭터의 기본 정보만 갱신합니다. 저장된 목록이 있으면 전체 목록 API를 자동 호출하지 않으며 등록하지 않은 캐릭터는 저장된 정보를 유지합니다. 등록 캐릭터가 없으면 기본 정보 자동 조회도 건너뜁니다. 캐릭터 카드마다 한국 시간 기준 마지막 갱신 날짜·시각을 표시하며, 조회 실패나 저장된 정보 복원은 갱신 시각을 바꾸지 않습니다. 기존 저장 파일은 최초로 읽을 때 원래 저장 시각을 캐릭터별 갱신 시각으로 옮깁니다. 저장된 목록이 없는 첫 실행에는 전체 캐릭터를 불러옵니다. 페이지를 이동하거나 서버 필터를 바꿀 때는 목록을 다시 조회하지 않습니다. **새로고침** 버튼으로 전체 목록과 기본 정보를 직접 갱신할 수 있습니다. API 키를 변경해도 다른 키의 캐시를 보존하며, 저장된 키를 다시 연결하면 캐시를 재사용합니다.

**설정 → 시작 페이지**에서 내 캐릭터·스케줄러·수익·레벨·문의·알림·설정·API 키 중 앱 시작 시 열 페이지를 고를 수 있습니다. 저장된 API 키가 없으면 키 입력부터 표시합니다.

각 둥근 정사각형 카드에는 이미지, 이름, 직업, `Lv. 레벨 (경험치 비율%)`이 표시됩니다. 이미지는 `Stretch=None`으로 확대·축소 없이 원본 크기로 가운데에 표시합니다. 카드에 마우스를 올리면 월드와 조회 상태를 확인할 수 있습니다. 목록이 먼저 표시되고, 이미지와 경험치 비율은 OCID를 이용한 병렬 기본 정보 조회가 끝나는 대로 표시됩니다. 눈 아이콘은 클릭할 때마다 키 표시/숨기기를 전환하며, 아이콘 모양은 고정하고 활성 상태는 파란색으로 표시합니다. 기본 강조색은 제공된 ChatGPT 전송 버튼 이미지에서 추출한 `#3A83F7`입니다.

**새로고침**은 목록과 기본 정보를 다시 조회합니다. **중단**은 진행 중인 조회를 취소하고 이미 조회된 카드를 유지합니다. **키 변경**은 기존 키와 캐릭터 목록을 보존한 채 입력 화면을 엽니다. **저장된 API 키** 목록에서 이전 키를 다시 선택할 수 있습니다. **설정 → 현재 API 키의 대표 캐릭터**는 키마다 별도로 저장되며, 기본은 가장 높은 레벨의 캐릭터입니다. 대표 캐릭터는 저장된 키의 표시 이름과 문의의 기본 캐릭터로 사용합니다. 일부 기본 정보 조회가 실패하면 목록의 이름·직업·레벨을 유지하며 경험치 비율은 `—%`로 표시합니다.

## 로컬 데이터 관리

설정에서 `%LocalAppData%\MapleDay`의 파일 용량을 확인하고 새로고침할 수 있습니다. 빨간색 **데이터 삭제** 버튼은 확인 창에 `삭제`를 공백 없이 정확히 입력해야 활성화됩니다. 저장된 API 키, 캐릭터 목록, 스케줄러 날짜별 기록, 설정, 문의 연결 정보와 작성 중인 내용을 삭제한 뒤 앱을 종료합니다. 삭제한 문의 연결 정보는 기존 문의 답변을 확인하는 데 필요하므로 확인 창에 해당 영향을 안내합니다. 서버의 문의·메일과 실행 파일은 삭제하지 않습니다. 진행 중인 캐릭터·스케줄러·문의 작업을 취소하고 저장 작업이 끝난 뒤 삭제하며, 데이터 폴더 밖의 경로나 파일 연결은 따라가지 않습니다.

## 스케줄러

스케줄러의 보드 위에는 별도의 주간·월간 보스 처치 수 문구를 표시하지 않습니다. 보드 안의 주간 보스 처치 제한과 캐릭터 이미지의 원형 진행도는 유지합니다. 주간 진행도에는 미등록 클리어도 포함하고 캐릭터당 12마리까지 표시합니다. 일일 보스 목록은 유지하며 일일 처치 수·수익 집계는 표시하지 않습니다. 같은 보스의 여러 난이도나 여러 날짜의 완료 플래그는 같은 주기에서 한 번만 계산합니다. 주간은 한국 시간 목요일 00:00, 월간은 매월 1일 00:00에 구간을 나눕니다. 스케줄러 화면을 열어 둔 상태에서도 날짜 변경을 확인해 다시 조회합니다.

왼쪽 **수익** 메뉴에는 스케줄러에 등록한 캐릭터의 이번 주·이번 달·누적 예상 결정 수익과 월별 캘린더를 표시합니다. 날짜 칸에는 +6.3억처럼 하루 수익과 처치 수를 표시하며 날짜를 클릭하면 해당 캐릭터와 잡은 보스, 난이도, 파티 인원, 수익, 주간 상한 제외 여부를 확인할 수 있습니다. 이전 달·다음 달·오늘 이동을 지원하고 기본으로 등록한 캐릭터를 합산하며 수익 페이지의 캐릭터 필터를 선택하면 해당 캐릭터만 표시합니다. 수익 필터는 스케줄러의 캐릭터 선택과 독립적이고, 스케줄러에는 수익 집계·캘린더 대신 콘텐츠 진행 현황을 표시합니다. 기존 수익 상세·합산 기록·지난 처치 기록의 펼침 목록은 제거했습니다. 보스 행의 오른쪽 버튼에서 파티 인원을 개별 설정하고 이름 옆에서 모리스9체로 확인할 수 있습니다. 버튼의 마우스 오버는 원본 화살표 발광 이미지를 사용하며 배경을 바꾸지 않습니다. 인원 설정 팝업은 버튼의 클릭·포인터 해제 처리가 끝난 다음 UI 큐에서 열어 같은 클릭으로 즉시 닫히지 않게 했습니다. 버튼을 누를 때 목록이 포커스를 가로채지 않으며 실제 드래그가 시작될 때만 전환합니다. 팝업은 바깥 클릭 또는 Escape로 닫히고 적용 버튼을 눌러 저장합니다. 미완료 btMove와 완료 btMoveCompleted의 normal·mouseOver·pressed·disabled 원본을 각각 사용하며 출처와 SHA-256은 Scheduler/party-button-manifest.json에 기록합니다. 기본 1인이며, 최초의 대적자·찬란한 흉성·림보·벨로나·유피테르·발드릭스는 최대 3인, 나머지는 최대 6인입니다. 인원을 변경하면 해당 날짜의 1인 결정 가격을 나누고 소수점 이하를 버립니다. 인원은 캐릭터·보스·초기화 주기별로 로컬 설정에 저장합니다. 월 수익은 달력 월 안에서 확인한 주간·월간 결정의 합이며 누적은 저장된 기록 전체입니다. 일일 결정과 API에 없는 실제 판매 여부·월드별 판매 한도는 제외합니다.

주간 수익은 사용자 요청에 따라 캐릭터당 금액이 높은 12개까지 합산합니다. 이 기준은 앱의 계산 기준이며 **게임의 캐릭터당 12개 판매 제한은 2026-09-17에 삭제**되었습니다([공식 패치](https://maplestory.nexon.com/news/update/813)). 가격표는 2026-10-06 확인 기준이며 [6월 변경](https://maplestory.nexon.com/News/Update/806), [9월 변경](https://maplestory.nexon.com/news/update/813)을 날짜별로 저장합니다. 검은 마법사의 가격은 각각 7월 1일·10월 1일부터 적용합니다. 벨로나 하드의 변경되지 않은 가격은 [위키 미러](https://namu.moe/w/%EA%B0%95%EB%A0%AC%ED%95%9C%20%ED%9E%98%EC%9D%98%20%EA%B2%B0%EC%A0%95)와 현행 가격표를 대조했습니다. 가격표 및 출처는 앱의 **수익 계산 기준 · 결정 가격표**에서 확인할 수 있습니다. `scripts/UpdateCrystalPrices.py`는 검토한 공식 표로 `src/MapleDay.Core/CrystalPrices.json`을 갱신하는 수동 개발 도구입니다.

누락된 날짜 사이에서 처음 관측하여 처치일을 확정할 수 없는 클리어는 수익 기록·주간·월간·누적 합계·캘린더에서 제외합니다. 원본 조회 기록은 보관하며, 앞 날짜의 미완료 응답을 확보해 처치일이 확인되면 수익을 다시 계산합니다. 미지원 보스 가격은 수익 합계에서 제외하고 미확인 건수를 표시합니다. 날짜 단위 API이므로 패치 당일 점검 전후를 구분할 수 없습니다. 기록이 없는 기간은 0원 수익이 확정된 기간으로 취급하지 않습니다.

넥슨 스케줄러 API는 2026-06-25 이후 데이터 중 요청일 기준 최대 14일 전까지 제공합니다([공식 안내](https://openapi.nexon.com/ko/support/notice/3482567/)). 실시간은 date 없이, 과거는 date=YYYY-MM-DD로 조회합니다. 처음 조회할 때 제공 가능한 과거 날짜를 모두 병렬 요청하며, 날짜별 응답은 `%LocalAppData%\MapleDay\scheduler-history`에 API 키 해시·OCID 해시별로 저장합니다. 확정된 과거 날짜는 재사용하고, 오늘 실시간 기록은 다음 날 과거 요청으로 최종 갱신합니다. 접속 기록이 없는 날도 저장하며 통신 실패 날짜는 다음 조회에서 재시도합니다. 저장한 날짜는 API의 14일 범위를 벗어나도 보존하며 **지난 보스 처치 기록**에서 이전 주·월 집계를 확인할 수 있습니다. 구간 시작부터의 기록이 없거나 과거 조회가 실패하면 **일부 기록**으로 표시합니다. 보존된 기록이 없는 14일 이전 날짜는 복구할 수 없습니다.

캐릭터 목록의 카드에서 **스케줄러에 추가**를 눌러 등록합니다. 스케줄러 화면의 캐릭터 추가 버튼·선택창·목록 이동 버튼은 제공하지 않습니다. 기본 화면은 등록한 모든 캐릭터를 표시합니다. 등록 캐릭터 목록은 스케줄러 화면 왼쪽의 144px 세로 사이드 영역에 배치하며 목록이 길어지면 세로로 스크롤합니다. 각 64px 카드에는 56px 원형 진행도, 닉네임·월드 아이콘·이번 주 보스 **n/12**를 표시하고 조회 전에는 **—/12**로 표시합니다. 캐릭터 이미지는 기존 108×120px 기준으로 자른 영역을 비율대로 축소합니다. 캐릭터를 클릭하면 해당 캐릭터의 진행 상황이 열리고 배경이 연한 회색으로 표시됩니다. 다시 클릭하거나 제목 표시줄 뒤로가기를 누르면 전체 보기로 돌아갑니다. **제거**는 앱의 스케줄러 표시 목록에서만 제거합니다. 오른쪽 보드는 창 크기와 관계없이 원본 786×622px로 표시하며 보드 목록과 캐릭터 목록은 독립적으로 스크롤됩니다. 창이 좁거나 등록한 캐릭터가 많으면 보드 영역의 가로·세로 스크롤로 확인할 수 있습니다. 새로고침·중단 버튼은 캐릭터 목록 아래에 표시합니다. 캐릭터 목록·레벨 페이지의 캐릭터 이미지 크기는 유지합니다.

추가한 OCID는 로컬 설정에 저장합니다. 현재 API 키로 불러온 캐릭터 목록에 있는 캐릭터만 표시하고 조회합니다. 화면을 열 때 조회 결과가 없거나 1분 이상 지났으면 등록한 캐릭터를 병렬 조회해 세로 목록의 진행도를 갱신합니다. **새로고침**은 등록한 모든 캐릭터를 다시 조회합니다. 조회 중에 캐릭터를 선택해도 다른 캐릭터의 조회는 계속 진행합니다. **중단**은 진행 중인 요청을 취소하고 이전 결과를 유지합니다.

게임의 `UI/UIMapleScheduler.img/main`에서 배경·행·헤더·버튼·완료 오버레이를 추출해 원본 786×622px 보드와 좌표를 사용합니다. 왼쪽은 일일·주간 콘텐츠, 오른쪽은 주간·일일·월간 보스 목록이며 각 영역이 독립적으로 스크롤됩니다. 마우스 휠 한 칸은 두 행(76px)을 이동합니다. 일괄 시작·완료는 비활성 이미지를 사용합니다. 보스 구역 순서는 주간 → 월간 → 일일입니다. 각 보스 구역 안에서는 입장 레벨이 낮은 순서로 표시하며, 200 미만은 게임 등록 화면의 자쿰 → 매그너스 → 파풀라투스 → 피에르 → 반반 → 블러디 퀸 → 벨룸 → 스우 → 데미안 순서를 사용합니다. 같은 280레벨인 벨로나는 찬란한 흉성 뒤에 표시하며, 같은 보스의 난이도는 API 순서를 유지합니다. 미등록 클리어 기록도 같은 정렬을 사용합니다. 게임 원본 나눔고딕(13px)과 모리스체(12px)를 스케줄러 안에 적용하고 앱의 나머지 화면은 Pretendard를 유지합니다. 원본 크기·좌표는 `src/MapleDay/Assets/Scheduler/ui-manifest.json`에 기록합니다. 게임 내 이동·퀘스트 시작/완료·등록 변경 기능은 API로 조작할 수 없으므로 해당 원본 이미지는 상태 표시용입니다. 보라색 화살표는 다음 등록 캐릭터로 이동하며 X는 캐릭터 선택 목록으로 돌아갑니다.

일일·주간 콘텐츠 및 보스는 `registration_flag`가 `true`인 것만 표시합니다. 미등록 보스라도 `complete_flag`가 `true`이면 **미등록 보스 · 클리어 기록**에 따로 표시합니다. 완료한 항목에는 반투명 회색 오버레이와 흰색 체크를 표시합니다.

보스 아이콘과 난이도 배지는 게임 데이터에서 추출한 로컬 PNG를 사용합니다. `UI/UIMapleScheduler.img/main/entity/bossIcon`에서 25×25px 보스·콘텐츠 아이콘 28개, `UI/_Canvas/UIBoss.img/BossList/{id}/Icon/normal/0`에서 림보·발드릭스·최초의 대적자·카이·찬란한 흉성·유피테르·메이린·벨로나의 25×25px 아이콘 8개, `UI/UIMapleScheduler.img/main/entity/difficulty`에서 60×18px 난이도 배지 5개를 추출했습니다. `_outlink`의 실제 Canvas까지 따라가며 원본 크기와 투명도를 유지합니다. 등록 보스와 미등록 클리어 보스 모두 동일한 아이콘을 표시합니다. API의 ‘시즌 보스 메이린’ 이름도 메이린 아이콘과 연결됩니다. 추출 경로·해시 기록은 `src/MapleDay/Assets/Scheduler/manifest.json`에 있습니다.

- 일일 퀘스트의 최대 진행도는 API의 `max_count`와 관계없이 100입니다. 완료 시 100/100을 표시합니다. 진행도가 100/100이어도 `quest_state`가 `2`가 아니면 완료 처리하지 않습니다. 주간 퀘스트도 `quest_state == "2"`일 때만 완료 처리합니다. `quest_state == "1"`에서 100 미만은 **진행 중**, 100/100은 파란 **완료** 버튼 이미지를 표시합니다. 실제 완료 체크는 `quest_state == "2"`일 때만 표시합니다. 0/누락 상태에는 시작 전 표시를 사용합니다.
- 에픽 던전은 `now_count`를 `STAGE 0`부터 `STAGE 5`까지 현재 스테이지만 표시하며 5스테이지에 도달하면 완료 처리합니다.
- 횟수형 콘텐츠는 `now_count >= max_count`일 때 완료합니다. 무릉도장·길드 미션 포인트·지하 수로·플래그 레이스는 기록을 표시하며 양수 기록이나 10/10만으로 완료 처리하지 않습니다. 최대 횟수가 0인 항목도 임의로 완료 처리하지 않습니다.
- 보스의 완료 여부는 `complete_flag` 값으로 판정합니다.

제공된 게임 설정의 레벨표로 일일 퀘스트 지역과 주간·월간 보스의 입장 레벨을 검사합니다. 조건 미달 행은 회색 이름과 원본 금지 아이콘을 표시하며 진행도·이동 버튼 대신 필요한 레벨과 캐릭터 레벨을 툴팁에 안내합니다. 일일 보스는 조건 검사를 제외합니다. 조건표에 없는 항목은 임의로 막지 않습니다. 기록이 완료인 항목에는 완료 표시를 유지합니다.

완료 콘텐츠는 원본 오버레이와 체크만 표시하고 버튼·진행도를 가립니다. 상세 진행도는 툴팁에서 확인할 수 있습니다. 완료 보스는 이동 버튼을 오버레이 위에 그리고 완료용 원본 버튼으로 표시해 두 번 어둡게 덮지 않습니다. 진행도 숫자와 최대값·단위 색상을 원본 설정처럼 나눕니다. 주간 보스 처치 제한은 원본 텍스트와 슬래시 기준으로 현재 횟수를 3px, 최대 횟수를 8px 왼쪽에 맞추고 최대 횟수는 원본의 옅은 색으로 표시합니다. 콘텐츠·퀘스트·보스 이름은 게임의 `Etc/NANUMGOTHIC_B.img/FONT_DATA`에서 추출한 실제 Bold `NanumGothicBold.ttf`를 사용하며, `SchedulerLabelPixels`에서 13px GDI 회색 안티앨리어싱으로 렌더링하고 일일 퀘스트·에픽 던전·길드 항목 이름은 가장자리 농도 1.5배를 사용하고 다른 콘텐츠·보스 이름은 추가 농도 보정을 제거해 `SchedulerLabel`의 이미지 캐시에 보관합니다. WinUI의 굵기 스타일을 적용하지 않고 원본 행의 배경색·글자색·말줄임을 유지합니다. 숫자 글꼴 `Morris9.ttf`는 게임의 `Etc/MORIS9.img/FONT_DATA`에서 추출한 원본 `MDmorris9`이며 다운로드 폴더의 모리스체와 다른 파일입니다. 원본에는 Regular 한 종류만 있으므로 게임의 12px·fontBold=1 설정으로 GDI에서 픽셀 글리프를 생성하고, `SchedulerNumber`가 원본 폭과 색상으로 표시합니다. WinUI의 FontWeight 보정이나 글꼴 재래스터화 없이 진행도·층수·점수·주간 미션 포인트·보스 파티 인원(숫자와 인 단위)에 공통으로 적용합니다. 진행도·점수·최대값·툴팁에는 천 단위 콤마를 붙이지 않습니다. 생성 스크립트는 `scripts/MakeSchedulerNumberGlyphs.py`, 출처·원본 해시는 `Assets/Scheduler/Numbers/manifest.json`에 있습니다.

게임 UI·숫자·보스·월드 아이콘은 빌드 시 `scripts/PrepareImageCache.py`로 미리 디코딩하고 `LocalImageCache`의 WriteableBitmap을 재사용합니다. 스크롤·마우스 상태 변경·행 재생성 시 URI 이미지를 다시 읽지 않으며, 숫자 컨트롤의 크기가 바뀌어도 이미지 요소를 재생성하지 않습니다. `scripts/Publish.ps1`이 이미지 캐시를 자동 준비합니다. 개발 환경에는 Python과 Pillow가 필요하며 배포 앱에는 필요하지 않습니다.

스크롤바는 스케줄러가 참조하는 공통 UI `UI/GuildUI2.img/guild/main/popup/gradeSetting/list/scroll:List`의 6×29px 손잡이와 `popup/groupList/list/scroll:List`의 7px 트랙을 추출했습니다. 로컬 `Scrollbar/manifest.json`에 원본 경로를 기록합니다. 마우스 올리기는 원본 pressed(thumb2), 누르고 드래그하기는 원본 hover(thumb1)를 사용합니다. 첫 휠 입력은 현재 위치에서 두 행(76px)을 300ms 동안 이동합니다. 같은 방향으로 연속 입력하면 이전 애니메이션이 최소 250ms 진행된 지점과 실제 진행 지점 중 더 멀리 간 곳에 다음 2.5행(95px)을 이어 붙입니다. 연속 입력 이동량은 첫 입력보다 25% 큽니다. 새 애니메이션은 실제 보이는 위치에서 300ms 동안 움직여 화면을 순간 이동시키지 않습니다. 반대 방향 입력은 현재 위치에서 반전하며, 끝에 도달하거나 드래그·키보드로 중단하면 이어 붙이기 상태를 지웁니다. 내부 목록은 InteractionTracker 기반 ScrollPresenter로 표시하고, 스크롤과 손잡이를 GPU 합성 애니메이션으로 움직입니다. 16ms UI 타이머·매 프레임 ChangeView·손잡이 Canvas 위치 변경을 제거해 앱에서 60fps를 제한하지 않습니다. 표시 프레임은 Windows 합성 엔진과 디스플레이 환경에 따르며 240fps 실측은 하지 않았습니다. WinUI의 기존 하드웨어 합성을 사용하므로 별도 하드웨어 가속 스위치는 없습니다. 일일·주간·보스 목록 안쪽을 눌러 드래그하면 잡은 위치가 포인터 이동 거리와 1:1로 즉시 따라가고 놓은 자리에서 멈춥니다. 버튼 위에서 드래그할 때는 버튼 클릭을 취소하며, 움직이지 않고 누르면 인원 설정을 엽니다. 손잡이 드래그·트랙 클릭·방향키·PageUp/PageDown·Home/End로 이동할 수 있습니다.

공식 API는 당일 접속 기록이 없는 캐릭터의 스케줄러 기록을 제공하지 않을 수 있습니다. 조회 실패는 캐릭터별로 표시하고 이전 결과가 있으면 유지합니다.

캐릭터를 선택하면 연한 회색 배경으로 표시합니다. 선택 변경은 이미 생성된 보드의 표시 여부만 바꾸며 이미지·보드 재생성과 추가 API 조회 없이 반영합니다.

## 알림과 자동 실행

익스트림 몬스터파커 알림은 오늘의 상태만 보지 않고 이번 목요일 이후 저장된 완료 기록도 확인합니다. 완료 관측은 같은 날짜의 이후 응답이 0으로 돌아와도 보존합니다. 이번 주에 이미 완료한 캐릭터, 또는 같은 API 키·월드에서 등록한 두 캐릭터의 완료가 확인된 경우 이 퀘스트를 알림에서 제외하며 목요일 00:00에 새 주 기준으로 다시 판단합니다. 확인 가능한 기록에 완료가 없다면 게임의 월드 완료 목록을 임의로 추정하지 않습니다.

메이플 유니온 퀘스트는 기본적으로 알림에서 제외합니다. 기존 설정에도 기본 꺼짐을 적용하며, **알림 → 설정 → 메이플 유니온 퀘스트 알림**에서 켤 수 있습니다. 정시 알림과 앱 시작 알림에 함께 적용하고, 스케줄러의 퀘스트 표시나 다른 일일 퀘스트 알림에는 영향을 주지 않습니다.

알림 메뉴는 받은 콘텐츠별 알림 목록을 먼저 표시합니다. 오른쪽 위 **설정** 버튼을 눌러 전체·종류별·시작 알림, 알림 시간과 Windows 알림 연결을 설정합니다. **알림으로 돌아가기** 또는 제목 표시줄 뒤로가기로 목록에 돌아올 수 있으며, 메뉴를 다시 열거나 Windows 알림으로 들어오면 항상 목록부터 표시합니다. 설정 화면을 보는 동안 새로 도착한 알림은 목록을 열기 전까지 읽음 처리하지 않습니다.

왼쪽 **알림** 탭에서 일일 퀘스트·주간 퀘스트·주간 보스 알림 설정과 기록을 관리합니다. 전체 및 종류별 알림은 기본 활성화입니다. 기본 알림 시각은 한국 시간 매일 22:00(일일), 수요일 22:00(주간)이며 초기화 2시간 전입니다. 일일은 1~23시간 전, 주간은 1~167시간 전으로 조정할 수 있습니다. **앱 실행 시 바로 알림**은 기본 비활성화이며, 켜두면, API 키와 등록 캐릭터가 준비되는 즉시 정해진 알림 시간과 무관하게 미완료 항목을 확인합니다. 이 옵션 변경은 다음 실행부터 적용되며 전체·종류별 알림 설정을 따릅니다. 시작 시 등록된 캐릭터·활성 종류마다 실행당 한 번만 처리하고, 조회 실패 또는 해당 종류의 API 데이터가 없으면 2분 뒤 재시도합니다. 시작 알림은 로컬 기록과 Windows 알림에 함께 남기며, 알림 시각 전에 보냈어도 이후 정시 알림은 유지합니다. 정시와 시작 알림이 겹치는 같은 조회는 한 번만 보냅니다.

스케줄러에 추가한 캐릭터의 등록·입장 가능한 미완료 항목만 최신 API 응답으로 확인합니다. 100/100이어도 퀘스트 상태가 2가 아니면 미완료입니다. 주간 보스는 12마리 완료 시 알리지 않습니다. 성공적으로 확인한 캐릭터는 종류·초기화 날짜별로 확인 기록을 저장하여 재실행해도 중복 발송하지 않습니다. 조회 실패는 2분 뒤 초기화 전에 재시도합니다. 알림은 앱 실행 중 및 트레이 최소화 상태에서 동작하며, Windows 알림을 클릭하면 앱을 복원하고 알림 탭을 엽니다. 알림 기록은 최근 100개를 로컬에 보관하며 알림 탭을 열면 자동으로 읽음 처리합니다. 알림 목록이 열려 있을 때 도착한 알림도 바로 읽음 처리하고 상태를 저장합니다. 기록은 콘텐츠별 카드로 나누고 각 카드에 미완료 캐릭터의 닉네임과 서버를 행으로 표시합니다. 보스는 로컬 원본 아이콘을 사용하며 읽은 알림은 옅게 표시합니다. 기존 저장 기록도 같은 목록으로 복원하고 Windows 알림에는 미완료 콘텐츠 이름을 표시합니다.

설정의 **Windows 시작 시 자동 실행**은 기본 활성화입니다. 배포 앱을 실행하면 현재 사용자의 `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`에 바깥 실행기 `MapleDay.exe`의 절대 경로를 등록합니다. 설정을 끄거나 앱 데이터를 삭제하면 메요일의 시작 항목만 제거합니다. 다른 프로그램의 시작 항목은 유지합니다. 개발 빌드는 배포 실행기가 없으면 자동 실행을 등록하지 않습니다.

## API와 키

- 공식 요청 주소: `https://open.api.nexon.com/`
- 목록: `GET /maplestory/v1/character/list`
- 기본 정보: `GET /maplestory/v1/character/basic?ocid=...`
- 스케줄러: `GET /maplestory/v1/scheduler/character-state?ocid=...`
- 인증 헤더: `x-nxopen-api-key`
- `date`를 생략해 API가 제공하는 최신 기본 정보를 조회합니다.
- API 키는 목록 조회 성공 후 현재 Windows 사용자에 대한 데이터 보호(`LOCAL=user`)로 암호화해 `%LOCALAPPDATA%\MapleDay\api-key.dat`에 저장합니다. 다음 실행 때 자동 연결하며 키 변경 시에도 보존합니다. 키 목록과 키별 대표 캐릭터는 같은 방식으로 암호화한 `api-key-profiles.dat`에 저장합니다. 소스와 로그에는 키를 기록하지 않습니다.
- 입력란은 비밀번호 입력 방식이며 빈 입력의 플레이스홀더는 회색 `live_`입니다. 테스트용 키는 앱에 포함되어 있지 않습니다.
- 상세 조회는 최대 32개를 병렬 처리합니다. 최근 1초 구간의 요청 시작을 최대 500건으로 제한하며 HTTP 429 응답은 최대 2번 재시도합니다. 500건/초는 [서비스 단계 허용량](https://openapi.nexon.com/ko/guide/prepare-in-advance/) 기준입니다.
- 키 발급 링크: [내 애플리케이션](https://openapi.nexon.com/ko/my-application/)

`https://openapi.nexon.com/`은 키 발급과 문서 사이트입니다. 전달받은 해당 호스트로 API를 호출하면 404가 반환되어, [넥슨 공식 가이드](https://openapi.nexon.com/guide/request-api/)의 요청 호스트를 사용했습니다.

## 개발

.NET 10 SDK와 Windows 빌드 환경이 필요합니다. 솔루션 파일은 `MapleDay.sln`이며 UI 프로젝트는 x64를 대상으로 합니다. Windows App SDK 2.5.1과 WinUI 3을 사용합니다.

EXE 설치 프로그램을 만들려면 Inno Setup 6이 필요합니다. `scripts/Publish.ps1`은 MSIX의 검증된 버전으로 `artifacts/Installer/MapleDay-Setup-버전-x64.exe`도 생성합니다. 기존 게시 폴더에서 설치 프로그램만 다시 만들 때는 `scripts/Build-Installer.ps1`을 실행합니다. 설치는 현재 사용자 계정에 적용되며 제거 시 저장된 사용자 데이터는 유지합니다.

```powershell
dotnet build src/MapleDay/MapleDay.csproj -c Release -p:Platform=x64
dotnet test tests/MapleDay.Core.Tests/MapleDay.Core.Tests.csproj -c Release
dotnet test tests/MapleDay.Storage.Tests/MapleDay.Storage.Tests.csproj -c Release
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Publish.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/Test-MSIX.ps1
```

모든 실행 가능한 테스트·배포 빌드는 `scripts/Publish.ps1`로 `artifacts/MapleDay` 한 폴더에 덮어쓰고 **MSIX도 함께 생성**합니다. 앱 본체는 `artifacts/MapleDay/App`에 게시하고 C++ 실행기를 바깥에 빌드합니다. 실행기에는 기존 메요일 아이콘을 포함하며 CRT를 정적으로 링크합니다. 실행기 빌드에는 이미 설치된 Visual Studio C++ x64 도구와 Windows SDK가 필요합니다. `MapleDay.exe --verify`는 창이나 앱을 실행하지 않고 본체·런타임 필수 파일의 존재를 검증합니다. 다른 `MapleDay-*` 실행 폴더는 만들지 않습니다.

MSIX 출력은 `artifacts/MSIX/MapleDay.msix`, 공개 인증서는 `MapleYoil.cer`, 직접 설치 안내는 `INSTALL.txt`, Store 제출 안내는 `STORE-SUBMISSION.md`입니다. Store 앱 표시 이름은 예약된 이름인 **메요일**, 제작자는 **MapleYoil**, Store 퍼블리셔 표시 이름은 할당 값인 **메요일**입니다. 패키지 이름은 `ABB731EC.2576917430647`, Publisher는 `CN=6E3CA1EF-722B-49DC-A96F-96F95E7B9BB8`이며 Store ID는 `9N133XQDNS1F`입니다. .NET과 Windows App SDK를 포함한 x64 패키지이며 Windows 10 2004(19041) 이상을 대상으로 합니다. 기존 로고를 Windows 패키지에 맞는 크기로 변환합니다. 설치형 앱은 패키지의 StartupTask로 자동 실행을 관리하고, 알림 COM 활성화 설정을 포함합니다. 기존 실행 폴더의 DLL·에셋은 계속 `App` 내부에 둡니다.

빌드에서 사용하는 자체 서명 인증서는 현재 사용자의 개인 인증서 저장소에서 재사용하며 개인키는 내보내지 않습니다. 직접 설치하는 테스트 PC에는 공개 인증서만 **로컬 컴퓨터 → 신뢰할 수 있는 사용자(Trusted People)**에 등록한 뒤 MSIX를 설치합니다. Store 제출에는 MSIX만 업로드하며 인증서 등록이 필요하지 않습니다. 빌드가 인증서를 신뢰 설치하거나 앱을 설치·실행하지는 않습니다. [Microsoft 인증서 안내](https://learn.microsoft.com/en-us/windows/msix/package/create-certificate-package-signing)를 따릅니다. 정식 인증서가 있으면 `-CertificateThumbprint`로 현재 사용자 저장소의 인증서를 지정할 수 있으며 Subject는 `CN=6E3CA1EF-722B-49DC-A96F-96F95E7B9BB8`과 일치해야 합니다.

성공한 패키지의 버전은 `artifacts/build/msix/last-version.txt`에 기록하고 다음 빌드에서 세 번째 숫자를 증가시킵니다. Store가 예약한 마지막 숫자는 항상 0입니다. 버전을 직접 지정하려면 `scripts/Publish.ps1 -PackageVersion 1.0.1.0`을 사용합니다. `PreparePackageResources.ps1`은 Store 패키지 이름으로 `resources.pri`를 재색인하고 글꼴·이미지·내장 XAML을 포함한 모든 리소스의 보존을 확인합니다. `makeappx.exe`의 스키마·의미 검증과 `signtool.exe`의 SHA-256 서명 이후, `scripts/Verify-MSIX.ps1`이 Store 식별자·버전·공개 인증서·CMS 서명·서명에 포함된 블록맵 해시·모든 파일 블록 해시·런타임 파일을 확인합니다. 검증이 성공한 후에만 배포 MSIX를 교체합니다. 패키지 생성은 [Microsoft MakeAppx 가이드](https://learn.microsoft.com/en-us/windows/msix/package/create-app-package-with-makeappx-tool)를 사용합니다.

- `src/MapleDay.Launcher`: DLL이 없는 네이티브 실행기와 기존 메요일 아이콘 리소스

- `src/MapleDay.Core`: 응답 모델, 인증 헤더, API 요청, 호출 간격·재시도
- `tests/MapleDay.Core.Tests`: 계정 전체 파싱, OCID 이스케이프, 경험치 정밀도, 키 오류, 오류 응답 비노출, 호출 제한 재시도, 취소, 일부 조회 실패, 동시 조회, 초당 제한 테스트
- `tests/MapleDay.Storage.Tests`: 실제 Windows 암호화 저장·복원·교체·삭제 테스트

## 레벨과 경험치 히스토리

왼쪽 **레벨** 탭에서 스케줄러에 등록한 캐릭터의 레벨·보유 경험치·오늘 획득 경험치·최근 7일 일평균 획득 경험치와 예상 레벨업 시간을 확인합니다. 획득량은 `+10.0조 (n%)` 형식이며 %는 현재 레벨의 필요 경험치 기준입니다. 오늘 획득량은 `date` 없이 조회한 실시간 기본 정보와 전날의 확정 기록을 비교하며 레벨 상승도 보정합니다. 비교할 전날 기록이 없거나 아직 제공되지 않았다면 비교 기록 부족으로 표시합니다. 오늘의 미확정 획득량은 최근 7일 평균이나 예상 시간 계산에 사용하는 평균 속도에 포함하지 않습니다. 캐릭터를 선택하면 7일 막대그래프와 실제 데이터가 있는 날짜만 표시한 히스토리 목록을 볼 수 있고, 설정의 시작 페이지에도 레벨을 선택할 수 있습니다. 데이터가 없는 날짜의 캐시는 유지하여 재조회하거나 누락 구간을 이어 계산하지 않습니다.

기본 정보 API의 `date`로 2023-12-21 이후부터 캐릭터 생성일을 고려한 모든 날짜를 최초 수집합니다. 전날 기록은 한국 시간 02:00부터 제공되므로 그 이전에는 이틀 전까지 완료된 날짜를 사용합니다. 최근 8개 날짜부터 우선 조회하여 7일 평균을 표시하고 오래된 날짜를 이어서 수집합니다. 키·캐릭터별로 경험치 숫자와 비율만 로컬에 저장하며 이미 저장한 과거 날짜와 명시적으로 데이터가 없는 날짜는 재조회하지 않습니다. 이후에는 현재 정보·새로 제공되는 날짜·실패하거나 손상된 날짜만 조회합니다. 64일씩 중간 저장하며 수집 중단 후에도 성공한 기록은 유지해 다음 조회에서 이어받습니다. API 키는 기록 파일이나 경로에 평문으로 저장하지 않습니다.

평균은 한국 시간 기준 최근 완료된 7일 각각의 전날 대비 경험치 변화로 계산하며 접속하지 않아 변동이 없는 날도 0으로 포함합니다. 누락된 비교 날짜는 0으로 간주하지 않고, 7일을 모두 계산할 수 없으면 데이터 부족으로 표시합니다. 레벨 상승은 해당 레벨의 API 경험치 수치·비율에서 계산한 필요 경험치로 보정하며 API 비율 반올림의 영향을 받을 수 있습니다. 여러 레벨이 한 번에 상승하여 중간 레벨의 필요 경험치를 확인할 수 없는 경우 획득량을 만들어내지 않습니다. 경험치 감소는 음수 변화로 유지합니다. 예상 시간은 현재 남은 경험치와 7일 평균을 사용하며 증가량이 없거나 최고 레벨인 경우 별도로 표시합니다. 경험치 기록도 설정의 앱 데이터 용량·삭제 대상에 포함됩니다.

Windows 자동 실행은 설정에서 트레이에 최소화 / 창 열기 중 선택할 수 있으며 기본은 트레이에 최소화입니다. EXE 시작 항목에는 `--startup`을 전달하고 MSIX는 StartupTask 활성화를 구분합니다. 직접 실행과 알림 클릭은 창을 열며 이미 실행 중인 앱에 자동 실행 요청이 들어와도 창을 앞으로 가져오지 않습니다. 트레이 아이콘을 등록하지 못하면 창을 표시합니다. 창을 처음 열기 전에도 캐릭터 갱신과 문의 답장·콘텐츠 알림 확인을 시작하며 초기화는 한 번만 수행합니다.

설정의 기본 창 크기에서 가로·세로 픽셀 값을 저장할 수 있습니다. 현재 창 크기로 설정은 창 테두리를 포함한 현재 크기를 저장하고, 초기화는 1200×800px로 되돌립니다. 변경은 다음 실행부터 적용됩니다.

알림 목록의 **모두 비우기**로 저장된 알림을 모두 지우거나 각 알림 오른쪽의 **삭제**로 개별 삭제할 수 있습니다. 삭제는 로컬에 저장해 다음 실행에도 유지하고, 발송 확인 기록과 알림 설정은 유지해 같은 알림을 다시 보내지 않습니다. 삭제 저장에 실패하면 기존 목록을 유지하며 알림이 없는 경우 모두 비우기는 비활성화됩니다.

캐릭터 서버 필터와 카드 목록 사이는 12px로 표시하고, 닫힌 안내·숨긴 로딩 행의 여백은 남기지 않습니다. 알림의 모두 비우기는 제목 줄에서 설정 버튼 왼쪽에 표시하며 알림 설정 화면에서는 숨깁니다. 닫힌 알림 안내도 레이아웃에서 제외합니다.

레벨 화면에는 최근 완료된 7일의 보유 경험치 자체를 선 그래프로 표시합니다. 기존 막대 그래프는 일별 획득량을 표시합니다. 선 그래프는 날짜·경험치 축과 0을 포함한 선형 눈금을 사용하고, 기록이 없는 날짜는 선을 끊으며 —로 표시합니다. 그래프의 점에 마우스를 올리거나 키보드로 초점을 이동하면 해당 날짜의 보유 경험치·레벨·경험치 비율을 확인할 수 있습니다. 레벨업으로 보유 경험치가 초기화되면 그대로 하락한 값으로 표시합니다. 창 크기에 따라 그래프 폭을 조절하며 좁은 화면에서는 날짜 눈금을 줄입니다. 오늘의 실시간 경험치는 7일 그래프에 포함하지 않습니다.
